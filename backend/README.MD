# AeroBag API

Серверная часть клиент-серверного приложения для организации доставки багажа из аэропортов. 

## Стек технологий
- **Язык:** Python 3.11
- **Фреймворк:** FastAPI
- **База данных:** PostgreSQL
- **ORM:** SQLAlchemy
- **Файловое хранилище:** MinIO S3-совместимое
- **Аутентификация:** JWT, bcrypt
- **Инфраструктура:** Docker, Docker Compose

## Функциональные требования

1. **Регистрация и аутентификация.** Система должна позволять пользователям регистрироваться по email и паролю, а также входить в систему с получением JWT-токена.
2. **Ролевая модель.** Система должна различать три роли: клиент, курьер и администратор.
3. **Создание заказа.** Клиент должен иметь возможность создать заказ на доставку, указав номер рейса, аэропорт, адрес доставки, описание багажа и стоимость.
4. **Загрузка документов.** Клиент должен иметь возможность загружать подтверждающие документы через presigned URL в хранилище MinIO.
5. **Оплата заказа.** Клиент должен иметь возможность оплатить заказ в демо-режиме, после чего заказ переходит в статус ожидания курьера.
6. **Назначение курьера.** Администратор должен иметь возможность назначать свободного курьера на оплаченный заказ.
7. **Управление статусами.** Курьер должен иметь возможность менять статус заказа.
8. **Отмена заказа.** Клиент должен иметь возможность отменить заказ до момента оплаты, а администратор на любом этапе, кроме завершенных.
9. **Система уведомлений и служба поддержки.** Система должна формировать уведомления о ключевых событиях и поддерживать встроенный чат  для связи клиентов/курьеров с администратором.
10. **Мониторинг и логирование.** Система должна фиксировать все HTTP-запросы и действия пользователей в базе данных, а администратор просматривать логи через API.


## Нефункциональные требования

1. **Производительность.** Время отклика API для основных операций не должно превышать 500 мс.
2. **Безопасность паролей.** Пароли пользователей должны храниться в базе данных только в виде криптографических хешей.
3. **Безопасность авторизации.** Доступ к защищенным эндпоинтам должен осуществляться только при наличии валидного JWT-токена.
4. **Безопасность файлов.** Прямой доступ к файлам документов должен осуществляться только через временные подписанные ссылки.
5. **Надежность.** Сервер должен корректно обрабатывать ошибки и валидировать входящие данные.
6. **Масштабируемость.** Файловое хранилище должно быть вынесено в отдельный S3-совместимый сервис.
7. **Кроссплатформенность.** Приложение должно быть упаковано в Docker-контейнеры для запуска на любой ОС.
8. **Логирование.** Все входящие запросы должны автоматически логироваться.
9. **Наблюдаемость.** Администратор должен иметь программный доступ к системным логам для мониторинга.
10. **Совместимость.** Все ответы API должны быть в формате JSON.

## Структура проекта

```text
air_bag_service/

│   │   ├── api/v1/            # REST эндпоинты

│   │   │   ├── users.py       # Управление пользователями
│   │   │   ├── orders.py      # CRUD заказов
│   │   │   ├── documents.py   # Загрузка/скачивание файлов
│   │   │   ├── notifications.py # Уведомления
│   │   │   ├── logs.py        # Логи системы
│   │   │   └── support.py     # Чат поддержки, тикеты
│   │   ├── core/              # Конфигурация, безопасность, БД
│   │   ├── models/            # SQLAlchemy модели
│   │   ├── schemas/           # Pydantic схемы
│   │   ├── services/          # Бизнес-логика
│   │   └── tests/             # Unit-тесты
│   ├── requirements.txt
│   └── Dockerfile
└── docker-compose.yml          # PostgreSQL + MinIO + Backend
```

## Запуск
**Через Docker**
```bash
cd air_bag_service
docker-compose up --build -d
```

После запуска сервисы будут доступны по адресам:

- **API сервер:** http://localhost:8000
- **Swagger документация:** http://localhost:8000/docs
- **MinIO:** http://localhost:9001 (логин: `minioadmin`, пароль: `minioadmin`)
- **PostgreSQL:** localhost:5432

При первом запуске база данных автоматически заполнится тестовыми пользователями:

- **Админ:** `admin@test.com` / `admin123`
- **Курьер:** `courier1@test.com` / `courier123`
- **Клиент:** `client1@test.com` / `client123`

## Основные эндпоинты API

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/v1/auth/register` | Регистрация |
| POST | `/api/v1/auth/login` | Вход и получение JWT |
| GET | `/api/v1/users/me` | Текущий пользователь |
| GET | `/api/v1/orders/` | Список заказов |
| POST | `/api/v1/orders/` | Создать заказ |
| PUT | `/api/v1/orders/{id}` | Обновить заказ |
| DELETE | `/api/v1/orders/{id}` | Отменить заказ |
| POST | `/api/v1/documents/upload-url/{id}` | URL для загрузки файла |
| GET | `/api/v1/notifications/` | Уведомления |
| GET | `/api/v1/logs/` | Системные логи |
| GET | `/api/v1/support/tickets` | Список тикетов |
| POST | `/api/v1/support/tickets` | Создать новый тикет |
| POST | `/api/v1/support/tickets/{id}/messages` | Отправить сообщение в тикет |
| PUT | `/api/v1/support/tickets/{id}/close` | Закрыть тикет |
| GET | `/api/v1/support/unread-count` | Счетчик непрочитанных сообщений для бейджа и закзов |


## На этапе сервера система имеет функционал:
- JWT аутентификация и авторизация.
- CRUD операции для пользователей, заказов и документов.
- Ролевая модель: client, courier, admin.
- S3-совместимое хранилище MinIO с генерацией presigned URL.
- История изменения статусов заказов.
- Система уведомлений с хранением в БД.
- Логирование всех запросов в базу данных.
- Docker-окружение в составе PostgreSQL, MinIO, Backend.
- Swagger документация.
